# إعداد خدمة الذكاء الاصطناعي (Cloudflare Worker)

تعمل الواجهة التشخيصية المحلية دون مفتاح API. ميزة AI تحتاج إلى Worker منشور ومزوّد متوافق مع واجهة OpenAI Chat Completions.

## 1) نشر الـ Worker

1. افتح لوحة Cloudflare وأنشئ Worker جديدًا.
2. انسخ محتوى `backend/cloudflare-worker.js` إلى محرر Worker، ثم انشره.
3. لا تضع مفتاح المزوّد داخل `index.html` أو أي ملف في GitHub.

## 2) إعداد المتغيرات والأسرار

من إعدادات Worker > Variables and Secrets، أضف:

- **Secret:** `AI_API_KEY` — مفتاح مزوّد النموذج.
- **Variable:** `AI_BASE_URL` — عنوان API الأساسي، دون `/chat/completions` في النهاية.
- **Variable:** `AI_MODEL` — اسم النموذج الذي يدعمه مزوّدك.
- **Variable:** `ALLOWED_ORIGIN` — `https://belaggouneseifeddine.github.io` بالضبط.

استخدم مزوّدًا تثق به، وتحقق من حدوده وتكلفته وسياسة الاحتفاظ بالبيانات قبل إرسال أي بيانات تشغيلية. لا تُدخل أسرار المصنع أو بيانات حساسة.

## 3) اختبار الاتصال من الهاتف

1. افتح التطبيق المنشور.
2. انتقل إلى **مساعد AI**، والصق عنوان Worker المنشور في حقل الرابط، ثم اضغط **حفظ الرابط على هذا الجهاز**.
3. جرّب وصفًا غير حساس، مثل: «مضخة طرد مركزي، تدفق منخفض، لا توجد قياسات مؤكدة».
4. إذا ظهرت رسالة خطأ، تحقق من متغيرات Worker وسجل الأحداث في لوحة Cloudflare، ولا تنشر المفتاح في رسالة أو لقطة شاشة.

## حدود الأمان المعروفة

- تحديد المعدل الموجود داخل الذاكرة هو حاجز مبدئي لكل نسخة Worker، وليس حدًا عالميًا موثوقًا بين جميع النسخ. قبل إتاحة عامة واسعة، فعّل Cloudflare Rate Limiting/WAF أو آلية مشتركة مناسبة.
- فحص Origin يساعد المتصفح على منع الاستخدام العابر للمواقع، لكنه **ليس مصادقة**؛ يمكن استدعاء API خارج المتصفح.
- مهلة الطلب وحدّ الحجم يقللان بعض مخاطر التعليق والاستهلاك، لكنهما لا يضمنان عدم تجاوز حصة مزوّد النموذج.
- مخرجات AI تقدير أولي فقط. لا تعتمد عليها منفردة لقرارات التشغيل أو العزل أو السلامة.

## ما لا يمكن تأكيده من المستودع وحده

لا يمكن تأكيد أن Worker منشور أو أن الأسرار والمتغيرات صحيحة أو أن رصيد مزوّد النموذج متاح؛ يلزم اختبار حي من حساب Cloudflare والمزوّد.
