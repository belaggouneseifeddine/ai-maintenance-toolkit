# Maintenance AI Toolkit

An Android-first, mobile-friendly industrial maintenance troubleshooting prototype.

## Experimental AI assistant
The interface includes an optional AI tab. Server-side options are `backend/cloudflare-worker.js` (Cloudflare Workers) and `api/chat.js` (Vercel Functions). Neither backend is deployed or connected yet. See [`docs/AI-SETUP.md`](docs/AI-SETUP.md) and [`docs/VERCEL-AI-SETUP.md`](docs/VERCEL-AI-SETUP.md). Never put provider API keys in the browser or public repository.

## Current prototype
The repository contains a static progressive web app (PWA) intended for phone browsers. The current Arabic-first interface includes:
- Structured fault entry for a wider set of equipment: pumps, motors, conveyors, compressors, hydraulic and pneumatic systems, actuated valves, VFDs, instrumentation, gearboxes, bearings, electrical control/PLC, and thermal systems.
- Symptom-specific follow-up questions for selected fault paths, with answers recorded in the generated inspection plan; questions are optional and do not claim a confirmed diagnosis.
- General symptom fallback guidance for slow cycles, intermittent faults, high pressure, and abnormal consumption.
- A source-backed fault knowledge base covering symptoms, safe checks, escalation, and limits.
- Safety reminders and a checklist.
- Local maintenance records saved in the browser on the current device.
- CSV export for saved records.
- A web app manifest and service worker for install/offline-shell support.

## Important limitations
- **AI is not connected.** Current suggestions are rule-based examples, not generated by an AI model.
- This is not a native Android APK.
- Browser-local records are not synchronized or backed up automatically.
- Offline behavior and installation must be tested on the deployed site and target phone.
- The CV link is a separate page and should be checked before public sharing.

## Safety principles
- Treat suggestions as support for qualified personnel, not a substitute for site procedures or manufacturer instructions.
- Isolate and verify energy sources before intervention; account for electrical, hydraulic, pneumatic, mechanical, thermal, and stored energy.
- Never bypass guards, interlocks, or protective devices.
- Do not invent specifications, torque values, pressure limits, wiring details, or part numbers.
- If information is insufficient or risk is high, stop and escalate.

## v0.2 diagnostic engine (branch under review)
- Offline rule-based pump-fault matching from `faults.json` and `diagnostic-engine.js`; weak matches are not guessed.
- Five general pump fault patterns with Arabic/French/English labels, keywords, causes, safe checks, and escalation criteria.
- Inspection-plan safety gate requires all checklist confirmations before rendering a plan.
- Local autosaved form draft, one-tap draft-to-log save, and draft clearing.
- Arabic/French/English interface strings, automatic RTL for Arabic, and remembered language preference.
- Local record search by equipment, status, and exact date; existing record key and CSV export are preserved.
- PWA shell cache v12 includes the engine, fault data, and translations.

The feature branch is not deployed by this change. Review the pull request and run the phone checklist before merging.
